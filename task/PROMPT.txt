请从零开发一个本地 CDC 采集归并器：接收会乱序、重放的变更流，持续生成 SQLite 中的账户余额镜像。使用 Windows 原生 Python 3.12，仅需 CPU，不使用 Docker、外部业务服务或现成流处理引擎。模拟源、归并器和测试都由你交付，无外部附件。

1. 模拟源通过本地 HTTP 分页返回事件；页有不透明的 next_cursor，相同游标重试返回相同内容。事件为 BEGIN(txid)、PUT(txid,op_index,account,balance)、DELETE(txid,op_index,account)、COMMIT(txid,commit_seq,op_count) 或 ABORT(txid)。PUT 是整数余额的覆盖写；同一事务内按从 0 连续编号的 op_index 执行。已提交事务的 commit_seq 从 1 连续递增，是唯一生效顺序。一个事务可以跨页，COMMIT 可以先于操作到达，不同事务交错，同一事件可完全重复；同一身份出现冲突内容须报错停止。输入最终包含所有操作及终结事件，并有明确 END；余额允许负数，DELETE 不存在账户为空操作。
2. 只能按连续 commit_seq 原子应用完整事务，读者不能看到半笔转账，也不能提前看到后序事务。等待缺失事务期间仍要继续拉取并把事件持久化，不能因内存缓冲已满而停止获取补齐事件。游标只代表已可靠接收的位置，不代表已应用位置；分页事件和接收游标、事务效果和应用水位分别必须一致提交。源可重放已确认页面。重启后从原数据库继续，不重复生效、不遗漏；END 后缺操作、缺序号或有未终结事务时必须明确失败。
3. 提供 run、status 和 snapshot 命令。snapshot 用一次数据库读事务导出当前连续水位及该水位的完整账户状态。构造至少 2 万笔跨账户事务，包含删除后重建、重复页和逆序完成事务；使用流式生成的独立答案核对每次抽样水位的全量状态。以可控同步点分别在接收事件但游标未提交、余额写入但事务未提交、提交成功但客户端尚未确认时终止自己启动的采集进程，重启后结果须与无故障基线一致。未完成事务可落盘，不得把整个事件流保存在内存中。

交付命令行工具、模拟服务、自动化故障测试及 Windows 运行说明，给出实际测试结果与未完成项。测试答案不能被采集器读取；故障注入不能仅抛一个被业务代码捕获的异常来代替进程终止。
